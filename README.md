# Song_Guard

부동산 담보·공유지분 기반 채권보전 및 경매회수 관리실. 저장소 실제 이름은 `NurionHoldings/SongGuard`, 제품/템플릿 이름은 `Song_Guard`입니다.

## 실행

Python 3.12 이상. 외부 Python 패키지가 필요하지 않습니다.

```bash
python manage.py create-user my-user
# 로컬 HTTP 개발 환경에서만 Secure 쿠키를 끕니다.
SONG_GUARD_SECURE_COOKIE=false python server.py
```

http://localhost:8000 에서 로그인합니다. 운영 계정 비밀번호는 12자 이상 필요합니다. 공개 가입은 기본 차단입니다. 개발환경에서 가입 화면을 시험할 때만 `SONG_GUARD_ALLOW_REGISTRATION=true`를 설정합니다.

Windows PowerShell:
```powershell
python manage.py create-user my-user
$env:SONG_GUARD_SECURE_COOKIE="false"
python server.py
```

## 운영 배포

```bash
docker compose up -d --build
docker compose exec songguard python manage.py create-user my-user
```

TLS 역방향 프록시를 로컬 8000 포트 앞에 구성하세요. 운영에서는 Secure 쿠키 기본값을 유지합니다. 데이터는 `/data/songguard.sqlite3`에 저장되며 Docker의 `songguard-data` 볼륨으로 유지됩니다. `PORT`와 `SONG_GUARD_DB`로 포트/DB 경로를 변경할 수 있습니다. 정적 호스팅만으로는 SQLite 서버를 실행할 수 없습니다.

상태 확인: `GET /health`. 백업: `python manage.py backup /안전한경로/songguard-backup.sqlite3`. 복구는 서버를 중지하고 백업 DB를 원래 DB 경로에 배치한 뒤 소유권/권한을 확인합니다. 원장, 계정, 감사, 첨부파일이 같은 DB에 포함됩니다. 백업에 민감정보가 있으므로 암호화 저장소에서 보관하고 복구를 시험하세요.

## 사용 순서

1. 채권 원장에 대여일·원금·이율·변제·담보한도를 등록하고 적용 근거를 기록합니다.
2. 담보 및 공유지분을 등록해 채권과 연결합니다. 담보 목적 지분이전과 일반 소유권은 구분합니다.
3. 경매사건을 등록하고 법원·사건번호·진행 단계·관련 기일을 확인합니다.
4. 기일 준비업무가 자동 생성됩니다. 법원 문서의 실제 기한을 확인하고 담당자를 지정합니다.
5. 사건 변수 등록 시 검토 업무가 생성됩니다. 미분류 변수도 기록할 수 있습니다.
6. 입찰·우선매수 화면에서 사건을 선택해 배당/자금 시나리오를 비교합니다.
7. 상세 화면에 증빙을 업로드합니다. 표시된 증빙 ID를 완료 또는 종결 필드에 입력합니다.
8. 실제 회수액은 채권의 변제내역에 반영합니다. 사건 회수액과 원장의 변제는 자동 중복 차감하지 않습니다.
9. 직접취득 부동산은 별도 자산으로 등록하고 인도·세금·운영·매각 업무를 연결합니다.

## 자동화 범위와 제한

이 버전은 **자체 채권관리 및 수동 문서 등록 기반 사건관리 시스템**입니다. 외부 법원 접수/전자서명, 등기 자동조회, 은행 입금확인, OCR/AI 원문분석, 외부 알림은 미연동입니다. 임의경매 신청·채권계산서·우선매수·특별지급의 검토용 초안을 제공하며 정식 제출 서식 확정과 접수는 사용자가 수행합니다. 화면에 외부 연동 상태와 계산 가정을 표시합니다.

채권 계산은 단일 연이율·365일 단리·비용→이자→원금 충당입니다. 이율 변경 및 법정 최고이율의 역사적 적용, 약정 충당, 공동담보/경합배당은 자동 판정하지 않습니다. 공유자 우선매수는 자격 후보의 안내이고 법률상 행사 가능성을 확정하지 않습니다. 모든 경매 변수의 완전한 자동 판단을 보장하지 않습니다.

자세한 설계: [ARCHITECTURE](docs/ARCHITECTURE.md), 법률 근거: [LEGAL_RULES](docs/LEGAL_RULES.md).

## 사람이 출력·접수하는 업무

`서류 생성 · 접수`에서 사건과 서식을 선택합니다. 임의경매 신청서, 채권계산서, 배당요구신청서, 공유자 우선매수신고서, 채권자 매수 특별지급 신고서, 보정서, 배당금 지급청구서 7종을 제공합니다.

1. 당사자·소유자·담보권·목적물·청구액·첨부목록을 입력합니다. 금액과 법률요건은 직접 확인합니다.
2. 필수 입력과 5개 확인사항을 완료해 출력본을 확정합니다. 확정 문서는 원본 자료가 바뀌어도 그대로 보존되며 수정은 새 문서로 생성합니다.
3. A4 미리보기에서 인쇄하거나 브라우저의 PDF 저장을 사용합니다. 별지 부동산 목록과 본인 보관용 접수 준비표를 구분합니다.
4. 서명·날인, 실제 첨부서류, 법원 요구 비용·보증을 준비하여 사람이 접수합니다.
5. 실제 출력 확인 후 접수증 파일·접수일·접수자·접수번호를 등록합니다. 임의경매 신청의 새 사건번호를 입력하면 사건에 반영됩니다.
6. 접수 후 진행·보정 안내 확인업무가 생성됩니다. 접수증 등록은 인용·배당·입금의 확인이 아닙니다.

자체 생성 서식이며 법원 공식 양식의 복제/인증본은 아닙니다. 관할 법원이 지정한 양식과 사건별 요구사항이 있으면 그 서식을 우선합니다. 접수 준비표는 신청서에서 분리해 본인이 보관합니다. 작성중 미리보기와 출력준비 문서를 구분하며, 최종 출력 전 내용과 적용법령을 확인하세요.

### 전자신청 연결 경로

`서류 생성 · 접수` 화면과 개별 서류에 대한민국 법원 전자소송포털(https://ecfs.scourt.go.kr/) 연결을 제공합니다. PDF 검토/저장 후 포털에서 로그인, 민사집행 서류·사건 선택, 해당 서류의 전자제출 지원 여부 및 요구 양식 확인, 담당자 제출, 접수증 보관으로 이어지는 안내 경로입니다.

현재 범위는 외부 포털 연결 안내만입니다. 사건 데이터·인증정보를 전달하지 않으며 링크 클릭으로 상태를 변경하지 않습니다. 종이 접수의 기존 상태·증빙 검증도 그대로 적용됩니다. 전자접수 기록은 아직 기존 종이접수 완료 기능에 입력하지 않습니다.

향후 연동은 별도 전자제출 어댑터로 확장합니다. 공식적으로 허용된 연결 수단과 인증 요건이 확인된 후 제출 방식(`paper`/`electronic`), 준비·제출·접수 응답 상태, 제출 식별자, 전자접수증을 별도 저장하고, 확인된 접수증을 기존 후속 업무 생성에 연결합니다. 외부 사이트를 열거나 전송 요청만 한 상태를 접수 완료로 처리하지 않습니다. 현재 API나 전자서명 기능을 구현한 것으로 간주하지 않습니다.

연결 주소 근거: 대한민국 법원 통합 안내 https://www.scourt.go.kr/work2025/helpinfo.html

### 관리자 홈화면 연결

방패·관제 나침반·부동산을 결합한 로고를 `static/logo.png`에 보관하고 로그인, 사이드바, 파비콘에 적용합니다. 홈 경고등은 마감 경과/오늘 마감 업무와 접수 대기 서류를 필터링합니다. 계기를 누르면 실제 업무·채권·사건 화면을 열고, 조작 패널은 등록 폼·접수·입찰 분석·감사기록으로 연결됩니다. 자료 연결 패널은 접수서류, 담보 원문 등록, 증빙 화면으로 연결됩니다. 회수액은 사건별 기록의 단순 합계이며 원장 잔액·회수율을 자동 확정하지 않습니다.

외부 법원·등기·은행의 자동 연동은 미구현입니다. 법원 전자신청은 공식 포털 연결 안내만 제공하며 자동 제출하지 않습니다. 로고 생성 명세: 투명 배경, 청록색·은백색 방패, 항공 관제 나침반 바늘과 부동산 실루엣, 어두운 계기판에서 작은 크기로 식별 가능한 단일 심벌.

## Netlify 배포

[GitHub → Netlify 전체 서비스 배포](docs/NETLIFY_DEPLOY.md)를 따르세요. 기본 배포는 Netlify Functions + Netlify Database(PostgreSQL) + Blobs이며 외부 Python 서버나 `SONG_GUARD_API_ORIGIN` 없이 빌드됩니다. 계정 비밀 설정은 Functions 전용 환경변수로 관리합니다. 위 Python/Docker 실행은 별도의 로컬·자가 운영 경로입니다.


### 세금 고지 · 납부 관리

자산관리의 세금 메뉴에서 취득세와 부가 세목, 보유·처분 세금, 소득 관련 세금 및 기타 고지를 등록합니다. 본인 납부와 채무자 조세채권을 분리하고 예상액은 확인 고지 미납액 합계에서 제외합니다. 고지서와 납부증빙은 세금 자료의 상세 화면에 업로드합니다. 전액 납부액·납부일·해당 자료의 증빙을 갖추어야 납부완료로 저장할 수 있습니다.

본인 납부의 확인된 실제 납부기한만 기한·조치에 반영합니다. 해당 세금에 원문 증빙을 업로드한 뒤 기한 확인 체크와 증빙 선택을 저장해야 안내가 생성됩니다. 예상·미확인 날짜와 채무자 조세 검토일은 납부일 안내에서 제외합니다. 기존 미확인 날짜는 재확인 전까지 안내하지 않으며 확인 해제 시 자동 업무도 제거합니다. 이의신청은 완료나 징수 유예로 처리하지 않습니다. 법정기일은 고지일과 별도로 기록하고 근저당·당해세·교부청구·배당표를 검토합니다. 국세청·지자체 공식 안내와 홈택스·위택스 연결 경로를 제공합니다(자료 검토일 2026-10-01). 고지 자동수집, OCR 판독, 세액·배당순위 자동확정 및 자동 납부는 구현하지 않았습니다.


### 자산 즉시 등록 및 화면 동기화

계기판의 자산 등록 버튼에서 소재지·자산 유형·면적·등록 평가액·권리 유형·지분·연결 채권을 저장합니다. 성공한 서버 저장만 목록에 즉시 반영하고 사건 및 세금의 연결 자산 선택에 사용합니다. 저장 중 중복 클릭을 차단합니다. 등기부를 자동 수집하거나 소유권을 변경하는 기능은 아닙니다.

같은 브라우저의 열린 탭은 변경 신호를 받고 서버 자료를 다시 조회합니다. 로그인한 다른 기기는 보이는 자산관리 화면을 15초마다 확인하고 포커스 복귀 시에도 갱신합니다. 작성 중인 창은 자동 갱신하지 않으며 서버의 버전 충돌 검사로 다른 기기의 수정 내용을 덮어쓰지 않도록 합니다.


### 아르카온 분석 · 점검 임무

계기판 또는 메뉴의 아르카온 분석·점검에서 임무를 실행합니다. 계정 소유 자료를 새로 조회하고 API 상태와 최대 20개 채권의 계산 실행을 확인합니다(나머지는 미실행 건수 표시). 규칙 기반 엔진은 자산·채권·경매사건·접수서류·세금·업무·변수의 누락, 연결, 증빙 연결 및 등록 기한을 검사합니다. 미확인 세금 날짜는 납부일 안내에 사용하지 않습니다.

결과는 원자료 확인, 조치 업무 작성, 보고서 저장 및 JSON 다운로드로 연결됩니다. 조치 등록의 미확인 기한은 자동 추정하지 않고 사람이 입력해야 합니다. 보고서는 생성 시점의 버전과 결과를 담고 계정별 DB·내보내기에 보관됩니다. 외부 원문 자동조회·문서 내용 판독·법률/입찰/납부 결정·코드 자율 수정 및 배포는 수행하지 않습니다. 코드 자체 검증은 GitHub CI에서 별도로 수행합니다.
